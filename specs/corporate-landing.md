# MIASO Corporate Catering — лендінг

## Мета

Односторінковий B2B-лендінг для MIASO (кейтеринг, Toronto & GTA), що конвертує рекламний/директ-трафік від office managers, HR, event planners у заявки на corporate catering quote через форми захвату лідів. Деталі дизайну й обґрунтування рішень — у `docs/superpowers/specs/2026-08-31-miaso-corporate-landing-design.md`, тут — конкретні, перевірювані вимоги до білда.

## Вимоги

1. **8 контент-блоків** з точним копірайтом з брифу (без перефразовування):
   - Block 1 Hero, Block 2 MIASO in Numbers (4 stat), Block 3 Catering Options (4 картки + bar-service callout), Block 4 Why MIASO, Block 5 How It Works (4 кроки), Block 6 Social Proof, Block 7 FAQ (7 питань), Block 8 Final Form
2. **Hero** реалізований за затвердженим мокапом: full-bleed фото зверху (без тексту-параграфа поверх фото), біла CTA-картка з negative-margin overlap на межі фото, pill + H1 на фото, параграф+btn+play-кнопка+trust-line у картці
3. **Візуальна система з трьох компонентів** (`Pill`, `Btn`, `Stat`) — жодного іншого стилю "плашки"/залитої форми в проєкті; кольори/шрифти точно за брендбуком (`#FFF9F3`/`#FFFFFF`/`#2B1F14`/`#C73D2D`/`#FFB973`, Baskervville + Josefin Sans з Google Fonts)
4. **3 форми захвату лідів**: quick-capture (Name, Email/Phone, Event Date) після Block 3 і після Block 5; full form (усі 12 полів з брифу) у Block 8. Усі три пишуть в один Google Apps Script Web App endpoint з міткою `source`
5. Кожен сабміт форми одночасно: (a) додає рядок у Google Sheet, (b) шле email-сповіщення, (c) шле повідомлення в окремий MIASO Telegram-чат
6. **Video modal** — play-кнопка (hero) відкриває модалку зі станом "Video launching soon"; URL відео підмінюється одним пропом, коли файл буде готовий
7. **Block 6 Social Proof** зверстаний з graceful placeholder-станом для відгуків/лого/фото гостей (контент прийде пізніше)
8. Зображення — конвертовані у WebP і стиснуті перед вставкою (жодне зображення в білді не важить як вихідний JPG 365КБ–1МБ)
9. Responsive: desktop (≥1280px) і mobile (≤480px) без горизонтального скролу, hero card-bridge коректно стекається на вузьких екранах
10. Деплой: GitHub Actions → GitHub Pages, репозиторій у клієнтському GitHub-акаунті, custom domain `events.miaso.ca`

## Обмеження

- Стек: React + Vite, один SPA-екран без роутингу (smooth-scroll якорі між блоками)
- Тільки наявні 50 фото з `Валентина мʼясо матеріали/` — жодних stock-фото
- Без бекенд-сервера: вся логіка форм — Google Apps Script Web App (безкоштовно)
- Репозиторій створюється на новому клієнтському GitHub-акаунті, авторизованому користувачем через `gh auth login` (не Owner0510, не Sloth-ops-hub)
- Жодних дій з паролями GitHub/GoDaddy від мого імені — DNS-запис (CNAME `events` → GitHub Pages) додає користувач сам у GoDaddy
- Копірайт блоків 1–8 — фінальний, з брифу; не перефразовувати без запиту користувача

## Крайні випадки

- **Мережева помилка при сабміті форми** → показати повідомлення про помилку, не втратити введені дані, дозволити повторну спробу
- **Порожні обов'язкові поля** → клієнтська валідація блокує сабміт, підсвічує проблемні поля
- **Подвійний клік по CTA/submit** → кнопка переходить у loading-стан і блокується на час запиту — без дубль-лідів
- **Один з трьох каналів (Sheets / email / Telegram) недоступний** → інші два все одно мають відпрацювати; збій одного не має валити весь сабміт
- **Дуже вузький екран (320–375px)** → hero card-bridge, stats-ряд, 4-card grid, обидві quick-форми і full form стекаються вертикально без горизонтального скролу
- **Фото не завантажилось** → є alt-текст, верстка не ламається (немає "стрибка" layout)
- **Block 6 без реального контенту на момент запуску** → акуратний placeholder-стан, не порожня секція і не lorem ipsum
- **Відео ще не готове** → play-кнопка веде на "Coming soon" модалку, не мертве посилання й не 404
